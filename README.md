# Markdown → DOCX для учебных работ

Это проект для агентов, который включает Codex skill для подготовки академических отчётов и детерминированный конвертер структурированного Markdown в Word-документ. Skill помогает агенту выбрать профиль, подготовить и проверить Markdown, а конвертер по JSON-настройкам собирает DOCX: текст, заголовки, кликабельное оглавление Word, нативные списки Word, таблицы, рисунки, листинги и список источников.

Форматирование не генерируется заново для каждой работы: оно хранится в JSON и применяется одинаково при каждом запуске.

## Установка в Windows

Нужен Python 3.10 или новее. В PowerShell из папки проекта выполните:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
```

После установки команда `md2docx` станет доступна в активированном окружении.

## Структура библиотеки

- `md2docx/config.py` загружает JSON-профили и объединяет наследуемые настройки.
- `md2docx/metadata.py` читает JSON-шапку Markdown и сопоставляет её поля с переменными титульника.
- `md2docx/converter.py` преобразует Markdown-блоки и собирает объект Word-документа.
- `md2docx/api.py` предоставляет функцию `convert_file()` для конвертации файлов.
- `md2docx/cli.py` реализует команду `md2docx`; `python -m md2docx` тоже поддерживается.
- `md2docx/core.py` оставлен как совместимый фасад для старых импортов.

## Быстрый запуск

Оформление ФИТ с титульником из шаблона ИДЗ:

```powershell
md2docx .\examples\report.md `
  --config .\configs\fit-academic.json `
  --vars .\examples\report-vars.json `
  -o .\out\report.docx
```

Короткий каркас находится в [examples/report-template.md](examples/report-template.md). Полный справочный образец со всеми поддерживаемыми блоками — [examples/full-report-template.md](examples/full-report-template.md). Скопируйте подходящий файл, замените примерный текст своим и при необходимости измените JSON-данные титульника.

Команду можно вызвать и из Python:

```python
from md2docx import convert_file

convert_file(
    "report.md",
    "report.docx",
    "configs/fit-academic.json",
    "report-vars.json",
)
```

## Как устроен Markdown-файл

Для автозаполнения титульника поместите в самое начало Markdown-файла блок `{{json` с объектом фиксированной структуры:

```markdown
{{json
{
  "discipline": "Название дисциплины",
  "title": "Тема работы",
  "student": {"name": "Иванов Иван Иванович", "course": "3", "group": "Группа-001", "program": "00.00.00 Название направления"},
  "teacher": {"title": "доцент, кандидат наук", "name": "Петров Пётр Петрович"},
  "institution": {"short": "ОмГТУ", "department": "ПМиФИ", "year": "2026"},
  "work": {"type": "Домашнее задание"}
}
}}
```

Поля разделены явно: парсер не пытается угадывать ФИО, курс, группу или учёную степень по свободной строке. `title` — тема работы, а `work.type` — её вид (например, лабораторная работа или домашнее задание). Титульник ФИТ повторяет шаблон ИДЗ: верхний колонтитул содержит министерство, вуз и кафедру; затем идут вид работы, тема, дисциплина и, если задан, вариант; внизу колонтитула — город и год. Блок данных включает студента, курс, группу, направление и проверяющего. Поля `student.program` и `work.variant` указывайте только если они нужны; без `work.variant` отдельная строка варианта не печатается. Сведения об ОмГТУ, кафедре и годе задаются в `institution`.

Блок должен быть первым в файле и содержать корректный JSON-объект между строками `{{json` и `}}`. YAML и свободный текстовый формат шапки не разбираются. Дополнительный файл `--vars` необязателен и перекрывает одноимённые значения из Markdown. Неизвестное поле титульника останется как `{имя_поля}`, чтобы пропуск был заметен.

Основной текст делится пустой строкой на абзацы. Заголовки начинаются с `#`, `##` или `###`. В профиле ФИТ структурные разделы — `ВВЕДЕНИЕ`, `ЗАКЛЮЧЕНИЕ`, `СПИСОК ЛИТЕРАТУРЫ` и другие из профиля — распознаются по названию независимо от уровня Markdown, выводятся прописными буквами без жирного начертания и не нумеруются. Заголовки второго уровня (`##`) основной части автоматически получают номера `1.`, `2.` и далее; уже заданный номер сохраняется. Заголовок, набранный целиком капсом, автоматически приводится к обычному регистру с заглавной первой буквой. Если после введения основная часть начинается с заголовка `##` или `###`, конвертер вставляет перед ним заголовок первого уровня `ОСНОВНАЯ ЧАСТЬ`. Если он уже указан в Markdown, повторно не добавляется. Для третьего уровня (`###`) номер, например `1.1`, пока указывайте в Markdown.

Чтобы вставить кликабельное оглавление в профиле ФИТ, добавьте строку `# СОДЕРЖАНИЕ` перед основным текстом. Конвертер добавит поле Word по последующим заголовкам до третьего уровня и начнёт введение с новой страницы. Не заполняйте этот раздел вручную. В Windows при установленном Microsoft Word конвертер пересчитывает оглавление при создании DOCX. Если Word не установлен, откройте документ в Word; если список пуст, выделите документ (`Ctrl+A`) и обновите поля (`F9`).

Структурные заголовки, которые конвертер оформляет прописными буквами, начинаются с новой страницы. Колонтитул и подпись титульного листа отображаются только на первой странице; в основной секции используется обычный колонтитул профиля.

### Плагин Codex

Проект предназначен для работы агентов и содержит Codex skill, который описывает подготовку Markdown, выбор профиля, сборку и проверку DOCX. Сам skill не включает копию конвертера: он запускает библиотеку из корня этого репозитория командой `python -m md2docx`. Поэтому для работы skill репозиторий должен быть доступен в workspace агента, а Python и зависимости — установлены.

В каталоге `plugins/md-to-docx-academic` находятся только manifest и skill. После изменения skill или manifest синхронизируйте их с локальным каталогом плагина командой `python .\scripts\sync_plugin.py --destination "$env:USERPROFILE\plugins\md-to-docx-academic"`. Скрипт удаляет прежние копии библиотеки и примеров из указанной папки плагина. Для проверки используйте ту же команду с `--check`.

Отдельная строка `---` вставляет разрыв страницы. Конвертер не рисует в этом месте горизонтальную черту.

### Рисунки

Каждый рисунок размещайте отдельным абзацем. Подпись берётся из текста в квадратных скобках, а путь к картинке задаётся относительно `.md`-файла:

```markdown
В тексте сначала объясните, что показывает рисунок.

![Сравнение результатов](images/results.png)
```

Файл изображения должен существовать. Если путь неверный, программа остановит конвертацию и укажет, какой файл не найден.

### Таблицы

Перед Markdown-таблицей отдельной строкой напишите `Таблица:`, затем название:

```markdown
Таблица: Сравнение вариантов

| Показатель | Вариант А | Вариант Б |
|---|---:|---:|
| Точность | 0,91 | 0,94 |
```

Конвертер создаст настоящую таблицу Word и поставит над ней нумерованную подпись.

### Листинги

Перед блоком кода укажите название листинга:

````markdown
Листинг: Подготовка данных

```python
values = [0.91, 0.94]
print(max(values))
```
````

Код сохраняет пробелы, переносы строк и кавычки. Язык после открывающих обратных кавычек можно указать для читаемости Markdown; в DOCX используется шрифт кода из JSON-профиля.
Подпись листинга удерживается вместе с началом кода. Длинный блок может продолжаться на следующей странице, чтобы не оставлять большие пустые области.

### Формулы

Используйте разделители TeX: одинарные `$...$` для формулы внутри строки и двойные `$$...$$` для отдельной формулы. Формы `\(...\)` и `\[...\]` пока не распознаются. При сборке формулы преобразуются в нативные редактируемые уравнения Word (OMML), а не в картинки:

```markdown
Значение дискриминанта вычисляется как $D = b^2 - 4ac$.

$$
x = \frac{-b \pm \sqrt{D}}{2a}
$$
```

Отдельная формула выравнивается по центру. Выравнивание и интервалы настраиваются в `math.display_align`, `math.display_space_before_pt` и `math.display_space_after_pt`. Поддерживаемые конструкции зависят от используемых TeX-команд; если формула некорректна или не поддерживается преобразователем, конвертация завершится понятной ошибкой, а не оставит исходный TeX в DOCX. Формулы в обратных кавычках остаются обычным кодом. Автоматическая нумерация уравнений не выполняется.

### Списки

Обычные Markdown-списки преобразуются в нативные списки Word: номера и маркеры задаются нумерационными свойствами документа, а не символами в тексте. Упорядоченные списки поддерживают начальный номер, вложенные уровни получают дополнительный отступ. ГОСТ-профиль ставит тире для маркированных перечислений, цифры с закрывающей скобкой для нумерованных; маркер начинается с абзацного отступа 1,25 см, а текст и переносы выровнены в столбик. Параметры `lists.left_indent_cm`, `lists.hanging_indent_cm`, `lists.nested_indent_cm`, `lists.space_after_pt`, `lists.bullet_character` и `lists.ordered_suffix` настраивают вид списка. Библиография может отдельно переопределять маркеры в профиле.

### Список источников

Используйте заголовок из JSON-профиля и Markdown-список — один источник на пункт. Можно поставить маркер `-` или номер. Библиография отдельно следует настройкам профиля: в профиле ФИТ записи выводятся без маркеров и с абзацным отступом.

```markdown
# СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ

- Иванов, И. И. Название книги : учебное пособие / И. И. Иванов. — Москва : Издательство, 2024. — 256 с. — Текст : непосредственный.
- Название сайта : [сайт] / Организация. — URL: https://example.org/ (дата обращения: 23.09.2026). — Текст : электронный.
```

Конвертер сохраняет текст записи и не превращает свободное описание в ГОСТ автоматически: необходимые сведения об ответственности, публикации, объёме, URL и датах должны быть в Markdown заранее. В профиле ФИТ записи выводятся без нумерации с абзацным отступом первой строки 1,25 см, как в примере работы. Исходные тире, кавычки и латинское написание сохраняются. Переносы строк выполняет Word по ширине поля.

## Выбор оформления

Выберите профиль явно в параметре `--config`:

| Профиль | Что он задаёт |
|---|---|
| `configs/fit-academic.json` | Требования ФИТ из шаблона ИДЗ и структуру приложенных титульников |
| `configs/fit-gost-bibliography-7.0.100-2018.json` | Оформление ФИТ для основного текста и отдельный стиль списка источников по ГОСТ Р 7.0.100-2018 |
| `configs/gost-report-7.32-2017.json` | Профиль отчёта о НИР на основе ГОСТ 7.32-2017, включая поля, межстрочный интервал, титульный лист и номера страниц |

Примеры запуска профилей ГОСТ:

```powershell
md2docx .\report.md --config .\configs\fit-gost-bibliography-7.0.100-2018.json --vars .\report-vars.json -o .\out\report-fit-gost.docx

md2docx .\report.md --config .\configs\gost-report-7.32-2017.json --vars .\gost-report-vars.json -o .\out\report-gost.docx
```

ГОСТ 7.32-2017 относится к отчётам о научно-исследовательской работе. Используйте профиль, если этот стандарт подходит вашему заданию. ГОСТ Р 7.0.100-2018 задаёт библиографическое описание; он сам по себе не задаёт шрифт и поля всего документа. При необходимости настройте текст записей источников и титульные данные отдельно.

Профили могут наследовать общий профиль через поле `"extends"` и переопределять только нужные параметры. В титульных абзацах можно настраивать отступы, интервалы и позиции табуляции (`tab_stops_cm`, от левого поля страницы). Чтобы сделать свой вариант, скопируйте JSON-файл и измените значения в копии.

## Что проверить перед сдачей

- Заполнены ли поля титульного листа и не осталось ли `{placeholder}`.
- Существуют ли все файлы изображений.
- Указана ли подпись таблицы/листинга в отдельной строке перед блоком.
- Совпадает ли заголовок списка источников с одним из заголовков профиля.
- Проверены ли библиографические записи по стандарту и требованиям кафедры.
- Откройте DOCX в Word и просмотрите переносы страниц, подписи, таблицы, изображения и номера страниц. Пагинация может отличаться между Word, LibreOffice и установленными шрифтами.
